# 単体フォント検証ツール

`verify_font.py` はビルダーのパッケージを import せずに Noto Bene TTF を検証します。
このファイルだけを別ディレクトリにコピーして実行できます。Python 3.9 以上、
`fonttools` と `skia-pathops` が必要です。

```sh
python -m pip install fonttools==4.60.1 skia-pathops==0.8.0.post2
python validation/verify_font.py --font dist/NotoBene-Regular.ttf \
  --source vendor/noto/NotoSansCJKjp-Regular.otf \
  --json dist/validation.json
```

非ASCIIは元の文字を残し、右上の円形領域を切り抜いて丸囲みの感嘆符を付けます。円の直径は0.5 emです。
検証器もこの形状を独立に再構成し、生成されたTrueType輪郭と比較します。

## 実際の表示との違い

このツールが確認するのは、TTFの文字マッピング・輪郭・メトリクスです。
検査成功は、ブラウザやアプリが各コードポイントの字形を実際に描画することを意味しません。
ゼロ幅文字、双方向制御、異体字セレクタなどは描画前に解釈・省略され、結合文字や
送り幅0の文字は警告が重なる場合があります。ASCII制御文字も非ASCII警告の対象外です。

利用側では元の文字列と解析後のホスト名を検査し、特殊文字のコードポイントを可視表記する
警告と、対象の描画環境での確認を併用してください。詳細は
[READMEの特殊制御文字・不可視文字の限界](../README.md#特殊制御文字不可視文字の限界)を参照してください。

## 検証項目

- TrueTypeの必須テーブル、ファイル全体と各テーブルのチェックサム、glyph/loca/hmtxの整合性。
- Unicode format 12 cmapに全非ASCII Unicode scalar（U+0080–U+10FFFF、サロゲート除外）が存在し、各cmapの対応先が一致すること。
- Windows BMP用のformat 4 cmap（platform 3、encoding 1）が1つ存在し、U+FFFF未満の文字マッピングがformat 12と一致すること。format 4の終端に使われるU+FFFFと補助平面の文字はformat 12で保持します。
- ASCIIと非ASCIIが別グリフを参照し、非ASCIIの対応先がすべて印付きグリフであること。
- GSUB/GPOS・カラー描画・可変フォントなど、検証済みの輪郭を置換するテーブルが残存していないこと。
- 描画時に輪郭を変更できるTrueType命令を含まないこと。`fpgm`・`prep`・`cvt `テーブルと、全グリフ（ASCII・`.notdef`・fallbackを含む）の非空命令列を拒否します。元フォントの指定有無にかかわらず検査します。
- 印付きグリフが単純TrueType輪郭であり、左サイドベアリングが新しい輪郭の左端に一致すること。正の送り幅は新しい右端から0.05 em以上の余白を確保すること。
- 元フォント指定時：ASCIIのcmap・送り幅・左サイドベアリング・輪郭を維持すること。`.notdef`も元の輪郭・メトリクスを印なしで維持すること。
- 元フォント指定時：非ASCIIの対応先が正しい元グリフから生成され、文字と印が収まる送り幅を持つこと。正の送り幅は元の幅と新しい右端+0.05 emの大きい方、送り幅0は0のままです。元輪郭から余白付き円を差し引き、円環・感嘆符の棒・点を合成した形状を独立再構成すること。切り抜き用の円は交差計算を安定させるため制御点を整数化し、印そのものの円は丸めません。
- 元フォント指定時：未収録文字が元の`.notdef`に印を付けた共通fallbackを参照すること。空白は印だけを表示すること。fallbackにも同じ送り幅の規則を適用すること。

CFFからの二次曲線変換は1 unit精度で独立実行します。輪郭比較は開始点の循環移動と
輪郭順の違いを許容し、対応する点の座標を1 unit以内で確認します。
同じ元グリフを指す複数のコードポイントについて、輪郭再構成は一度だけ行います。

元フォントの指定有無にかかわらず、全印付きグリフから円環の外周・内周・感嘆符の
棒・点の4輪郭を独立に検出します。同じboolean演算を再実行しても一致してしまう
切り抜き不良を、この検査で検出します。JSONの`badge_checked`に検査数を記録します。

`--source`を省略した検査は元の輪郭が
保存されたことや正しい文字の対応先までは保証しません。成功メッセージとJSONに
元フォント比較を省略したことを明示します。位置を推定した印の照合は2 unit以内です。

終了コードは成功`0`、検査不合格`1`、入力ファイル・依存関係・実行エラー`2`。
JSONは`ok`、`error_count`、`errors`、検査した文字数などを含みます。
多数の不一致がある場合も全件のエラー数を集計し、詳細は先頭100件まで保存します。
