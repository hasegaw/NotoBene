# Noto Bene

**ホスト名に紛れた非ASCII文字を、警告マークで見つけやすくするフォント。**

Noto Bene は、Noto Sans CJK JP をベースに、ASCII以外の文字の右上へ丸囲みの「!」を付けたフォントです。URLバー、クリッカブルなリンクのURL、その他のホスト名表示に適用し、見た目が似た文字を使った偽サイトのホスト名に気づきやすくします。

普段見慣れたホスト名に見えても、別の文字が混ざっていることがあります。本フォントはその違いを視覚化し、詐欺サイトやフィッシングサイトへの意図しない誘導を避けるための確認を支援します。

## 表示例

ASCIIの `a` とキリル文字の `а` は、通常のフォントでは見分けにくい字形です。次のデモは、ホスト名の一部を想定した文字列を、元のNotoとNoto Beneで実際に描画したものです。

| 文字列 | 使用している文字 | Noto Beneでの表示 |
| --- | --- | --- |
| `amazon` | すべてASCII。`a` は U+0061 | 警告マークなし |
| `аmаzon` | 1文字目と3文字目がキリル文字 `а`（U+0430） | その2文字に警告マーク |

![通常のNotoとNoto Beneによるamazonとキリル文字混在文字列の比較](docs/images/amazon-demo.png)

警告マークは画像に後から重ねたものではなく、フォントに組み込まれた字形です。元の文字を残しつつ、マークと重なる部分を円形に切り抜いています。

## 想定する使い方

次のような、アクセス先のホスト名を確認する表示部分への適用を想定しています。

- **URLバー・アドレス欄**：入力したURLや、現在表示しているページのホスト名。
- **クリッカブルなリンクのURL**：リンク先のホスト名を含むURL表示、プレビュー、ツールチップ。
- **その他のホスト名表示**：メールやチャット内のリンク先確認、接続先一覧、アクセス確認画面など。

生成した `NotoBene-Regular.ttf` をアプリや表示環境に読み込み、対象部分のフォントファミリーに **`Noto Bene`** を指定します。ホスト名部分に適用することで、URLのパスやクエリに含まれる日本語などと区別して確認できます。

リンクでは、実際のリンク先URLから得たホスト名を表示する部分に適用してください。リンクのラベルだけに指定しても、そのラベルとリンク先が一致しているかは確認できません。

適用には、表示するアプリやブラウザ側でフォントを指定できることが必要です。TTFをインストールするだけで、すべてのブラウザのURLバーが自動的に切り替わる機能はありません。本リポジトリではフォントとビルド・検証ツールを提供します。

## 警告マークが示す範囲

警告マークは「この文字が非ASCIIである」ことを示します。正規の日本語ドメインなどにも付きます。アクセス先を判断する際に、ホスト名を注意して確認するための表示支援として利用してください。

ASCIIだけで構成された偽のホスト名にはマークが付きません。また、国際化ドメイン名が `xn--` で始まるPunycodeのASCII表記で表示されている場合も対象外です。

フォントが処理するのは、適用先で描画される文字列です。リンク先URLとの一致、リダイレクト先、サイトの内容や安全性の検査、アクセスの遮断は行いません。

### 特殊制御文字・不可視文字の限界

**警告マークが見えなくても、ASCIIだけの文字列であるとは限りません。マークの有無だけではアクセス先の安全性を判断できません。**

アプリや描画エンジンは、文字を描く前に制御文字を解釈したり、不可視文字を省略したりします。フォントの文字マップ（cmap）に警告付きグリフがあっても、そのグリフが実際に描画されるとは限りません。特に次の種類を考慮してください。

| 種類 | 例（コードポイント表記） | 見落としにつながる挙動 |
| --- | --- | --- |
| ゼロ幅文字・結合制御 | `U+200B`（ZWSP）、`U+200C`（ZWNJ）、`U+200D`（ZWJ）、`U+2060`（WORD JOINER） | 自身が表示されず、分かち書きや文字の結合にだけ影響する場合がある |
| 双方向制御文字 | `U+202E`（RLO）、`U+2066`–`U+2069`（方向分離制御） | 自身を表示せず、文字の見た目の順序を変える場合がある |
| 異体字セレクタ・結合文字 | `U+FE0F`、`U+0301` など | 別の文字と一緒に処理されたり重なったりして、警告が個別に見えない場合がある |
| ASCII制御文字 | `U+0009`（TAB）、`U+000A`（LF）、`U+000D`（CR）など | 非ASCIIへの警告の対象外で、描画前に解釈・除去される場合がある |

例えば、表示文字列 `ama\u200Bzon` はゼロ幅スペースの処理によって `amazon` と区別できなくなる可能性があります。ここでの `\u200B` は文字を説明するためのエスケープ表記で、実際の不可視文字はこの例に埋め込んでいません。これらの文字がすべて有効なホスト名として受理されるわけではなく、入力やリンクラベルの表示と、URL解析・IDNA処理後の接続先は区別する必要があります。

組み込み先では、フォントによる表示に加えて、次の処理を行ってください。

- 入力された元の文字列を、正規化や文字の削除で情報が失われる前に検査する。URLパーサーが確定した接続先ホスト名も別途確認する。
- 検出した特殊文字の位置と `U+200B` のような可視表記を、元の文字列の表示順やフォントに依存しない警告欄へ表示する。表示用の可視化をリンク先URLの書き換えに使わない。
- 実際に組み込むブラウザやアプリで、ゼロ幅文字・方向制御・結合文字を含むケースの表示を確認する。

本リポジトリの検証ツールはフォント構造と字形を検査します。全コードポイントのマッピング検証に成功しても、各アプリが特殊文字の警告を描画することまでは保証しません。`amazon` の比較デモはキリル文字の類似字形を確認する例で、特殊制御文字の表示検証を代替しません。

関連する仕様は、[Unicodeの識別子セキュリティ（UTS #39）](https://www.unicode.org/reports/tr39/)、[双方向表示アルゴリズム（UAX #9）](https://www.unicode.org/reports/tr9/)、[IDNAの文字マッピングと検証（UTS #46）](https://www.unicode.org/reports/tr46/)を参照してください。

## フォントの仕様

フォント名は **Noto Bene Regular** です。バージョンは [sources/font-version.txt](sources/font-version.txt) で管理し、フォント内部の版番号・固有識別子とビルドレポートへ反映します。

| 元の文字 | 出力 |
| --- | --- |
| ASCII（U+0000–U+007F）のうち Noto に収録された文字 | 元の輪郭・送り幅を維持 |
| Noto に収録された非ASCII | 元の字形の右上に丸囲みの「!」を付加。幅が足りない文字は送り幅を拡張 |
| 非ASCIIで、元の輪郭が空（全角スペースなど） | 丸囲みの「!」のみ。正の送り幅が足りなければ拡張 |
| Noto に未収録の非ASCII | 元フォントの `.notdef` に丸囲みの「!」を付加 |

丸囲みとその周囲に重なる元の輪郭は円で切り抜き、切断した輪郭を閉じてからバッジを加えます。文字の塗りや抜きは元の字形に従い、円の内部には「!」だけが残ります。フォントの `.notdef` 自体は元フォントの字形を変換したもので、バッジを付けません。

非ASCIIは U+0080–U+10FFFF の全 Unicode scalar value にマッピングします（サロゲート U+D800–U+DFFF は除外）。未割当文字・私用領域も対象です。ASCIIの制御コードは元フォントの収録状況に従い、通常の改行やタブなどはアプリが処理します。異体字セレクタ、結合文字、双方向制御、ゼロ幅文字などもcmapには収録しますが、アプリやシェーパーが不可視にしたり並べ替えたりすることがあります。フォントだけではコードポイントごとの表示を強制できません。

## ビルド

Python 3.9 以降を使います。CI は Python 3.12 です。

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/build.py
```

初回は公式 Noto リポジトリからフォントとライセンスを `vendor/noto/` に取得します。`sources/noto.lock.json` でコミット、URL、サイズ、SHA-256 を固定し、ダウンロード時もキャッシュ再利用時も検証します。壊れたキャッシュは再取得し、検証前のファイルで既存キャッシュを上書きしません。

生成物は `dist/` です。

- `NotoBene-Regular.ttf` — インストールして使用するフォント
- `build-report.json` — 加工件数、入力と出力のハッシュ、ビルド条件
- `OFL.txt` / `FONT-NOTICE.txt` / `noto.lock.json` — ライセンスと来歴

キャッシュ取得とビルドを分ける場合:

```sh
python scripts/download_noto.py
python scripts/build.py --offline
```

`--output-dir` で生成先を、`--cache-dir` でキャッシュ先を変更できます。CLIに指定した相対パスはカレントディレクトリ基準、既定値はリポジトリ基準です。既定のフォント日時は固定です。`SOURCE_DATE_EPOCH` を指定するとそのUnix秒を使用します。同じ入力・依存バージョン・日時での再ビルドは同じバイト列になります。

## バッジと字形

バッジの直径はフォントの em 高さの半分、**0.5 emに固定**します。幅の狭い文字でも縮小しません。正の送り幅を持つ文字では、円の右端を「元字形の右端」「元の送り幅の95%の位置」「0.55 emの位置」のうち最も右側に置きます。上端は「元字形の上端」と「0.85 emの高さ」のうち上側です。送り幅0の文字は元字形の右端を基準にし、輪郭も空なら0.95 emの位置を使います。円の周囲には半径の12%分の余白を切り抜き、丸枠の線幅は半径の16%です。「!」は台形の縦棒と丸い点で構成します。

非ASCIIのアウトラインをコンポーネントまで展開し、Skia PathOps の non-zero winding 規則で塗り領域を扱います。元の塗り領域から余白を含む円形の領域を差し引くブーリアン差分を取り、その円に交差する輪郭を切り詰めて閉じます。切り抜き用の円だけは、差分演算の数値安定性のために制御点を整数化します。丸枠と「!」には元の曲線を使います。その後、円の輪郭と「!」を加えます。単にバッジを重ね描きする処理ではないため、文字の線がバッジ内を横切ることはありません。重なり、抜き、反転したコンポーネントも元の塗りに従って処理し、パス演算に失敗した場合はビルドを止めます。

ASCIIは元の輪郭とメトリクスを引き継ぎます。非ASCIIで正の送り幅を持つ文字は、元の送り幅と「加工後の輪郭の右端 + 0.05 em」のうち大きい方を出力の送り幅にします。細い文字にも円全体と右側の余白を収めるためで、幅が十分な通常のCJK文字は元の幅を保ちます。左サイドベアリングは加工後の輪郭の境界から再計算します。未収録文字の代替にも元の `.notdef` を基準に同じ幅調整を適用します。送り幅0の結合文字は0を維持するため、バッジが隣の文字に重なることがあります。Noto Sans CJK JP は等幅専用フォントではありません。

CFFの三次曲線はすべて、最大1 font unitの近似誤差（さらにTTF座標の整数丸めあり）で二次曲線へ変換します。元のヒンティング・カーニング・字形置換・縦書き情報は引き継ぎません。加工済みの字形が元の字形へ置換されないように、出力は新しいTTFとして構築します。ASCIIと非ASCIIが同じ元グリフを参照していても、出力では分離します。

文字マップは Unicode全範囲用の OpenType cmap format 12（platform 0/encoding 4 と platform 3/encoding 10）です。format 4 のみ対応する古い描画環境は対象外です。

## 検証

```sh
python -m unittest discover -s tests -v
python validation/verify_font.py \
  --font dist/NotoBene-Regular.ttf \
  --source vendor/noto/NotoSansCJKjp-Regular.otf \
  --json dist/validation.json
```

`validation/verify_font.py` はビルダーをimportしない単体CLIです。別ディレクトリにコピーして、同じ依存ライブラリを入れるだけで実行できます。`--source` を省くと出力TTFの構造、全非ASCIIマッピング、バッジの輪郭を確認します。指定するとASCII保持と、元の非ASCII全グリフの加工結果まで照合します。正常時は終了コード0、異常時は非0です。詳細は [validation/README.md](validation/README.md) を参照してください。

元フォントと加工後の文字を画像で比較する場合は、単独のプレビューCLIを使えます。

```sh
python validation/render_preview.py \
  --font dist/NotoBene-Regular.ttf \
  --source vendor/noto/NotoSansCJKjp-Regular.otf \
  --output dist/preview.png
```

ASCIIだけの `amazon` と、2つの `a` をキリル文字 `а`（U+0430）に置き換えた `аmаzon` の比較デモも生成できます。元のNoto Sans CJK JPとNoto Beneを並べ、丸囲みを含めて各フォントの実際の字形を描画します。

```sh
python validation/render_demo.py \
  --font dist/NotoBene-Regular.ttf \
  --source vendor/noto/NotoSansCJKjp-Regular.otf \
  --output dist/amazon-demo.png \
  --report dist/amazon-demo.json
```

`amazon-demo.json` には各文字のコードポイントと、バッジが付く位置を記録します。ASCII版はマークなし、キリル文字を混ぜた版は1文字目と3文字目（0始まりの位置 `[0, 2]`）にマークが付きます。

## GitHub Actions

`.github/workflows/build.yml` は push、pull request、手動実行に対応します。単体テスト → Noto取得 → TTFビルド → 独立検証 → 比較画像生成を実行し、配布ファイル・検証レポート・`preview.png`・`amazon-demo.png`・`amazon-demo.json` を `noto-bene` artifact として30日間保存します。通常のビルドは Release を公開しません。

公開は初期状態では無効です。GitHub の Actions 変数 `RELEASE_REPOSITORY` に公開先の `owner/repo` を設定すると、そのリポジトリでのみ手動公開できます。fork でも、`RELEASE_REPOSITORY` に fork 先の自分の `owner/repo` を設定すると、その fork の Release を公開できます。`ENABLE_SCHEDULED_RELEASES=true` を追加すると、毎週日曜9時（日本時間）にも更新を確認します。

Actions の **Release Noto Bene font** を `main` から `latest-noto` モードで実行すると、公式 Noto の対象フォント・ライセンスを確認し、未配布の入力がある場合だけ生成・検証・タグ作成・Release 公開を行います。自動取得した入力は専用のリリース用コミットに固定します。既存の lock で修正版を配布する場合は `pinned` モードで公開日（`YYYYMMDD`）と改訂番号（`1`〜`99`）を指定します。

```text
NotoBene-20261016-noto-f8d157532fbf-r01.zip
NotoBene-20261020-noto-f8d157532fbf-r02.zip
```

ファイル名は名前順で公開日順になります。ZIP には `NotoBene-Regular.ttf`・`OFL.txt`・`FONT-NOTICE.txt` の3ファイルだけを収録します。Noto の完全 SHA とビルダーの完全 SHA は別添の `release-manifest.json` に記録し、`SHA256SUMS` も添付します。公開済みのタグや配布物は上書きしません。初回設定、再実行、版番号の更新方法は [リリース手順](docs/releasing.md) を参照してください。

## ソースとライセンス

元フォントの公式配布情報は [Noto Sans CJK](https://github.com/notofonts/noto-cjk/blob/main/Sans/README.md) にあります。使用する版は [noto.lock.json](sources/noto.lock.json) の `revision` とファイル URL で確認できます。各配布に使用した Noto の完全 SHA と入力ファイルのハッシュ・サイズは、Release に別添する `release-manifest.json` で確認できます。

派生フォントは SIL Open Font License 1.1 で配布します。再配布時は `dist/OFL.txt` と `dist/FONT-NOTICE.txt` を同梱してください。原文を [sources/OFL.txt](sources/OFL.txt) に保存しています。元フォントは Noto Sans CJK JP、派生フォントのファミリー名は Noto Bene です。
